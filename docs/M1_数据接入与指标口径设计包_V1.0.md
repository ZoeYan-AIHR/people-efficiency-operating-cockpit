# 人效经营驾驶舱｜M1 数据接入与指标口径设计包

**版本：** M1 Baseline v1.0  
**适用范围：** 标准 Excel / CSV 聚合导入；业、人、财月度经营分析；不含个人绩效与薪酬明细。  
**确认基线：** 2026-08-31

---

## 1. M1 目标与边界

### 1.1 目标
用一套可审计的标准导入模板，完成以下闭环：

> 导入 → 字段映射 → 数据质量校验 → 对账发布 → 自动计算 → 看板 / 预测 / 预警 → 行动复盘

M1 的重点是建立**可信数据底座与统一指标口径**，不是以任意格式 Excel “一键正确分析”为承诺。

### 1.2 已确认口径

| 主题 | M1 选择 | 说明 |
|---|---|---|
| 数据接入 | 标准模板导入（推荐） | 首次允许字段映射；后续固定模板批量导入 |
| 人均有效产出分子 | 确认收入 | 不使用签约额、开票额或回款额替代；回款作为质量/现金护栏 |
| 利润口径 | 经营利润 | 所有“人均利润”“单位人工成本利润”统一引用经营利润 |
| 人工成本范围 | 全口径人工成本 | 薪酬、奖金、雇主成本、福利、招聘、培训、外包、离职补偿；各项可配置启用范围 |
| 人力分母 | 月均 FTE | 不用期末静态人数替代；兼职、外包、派遣等按 FTE 规则折算 |
| 发布约束 | 强制对账 | 任一阻断规则失败，不得发布到经营看板或预测中心 |

### 1.3 M1 不纳入范围

- 员工个人绩效排名、个人薪酬明细、个体预测；
- 未经财务确认的收入、利润与成本口径；
- 未审批的 HRIS、财务、CRM、项目系统直连；
- 历史样本不足时将预测替代预算或管理判断；
- 对未取得权限的敏感人才数据默认展示或导出。

## 2. 标准导入工作簿与最小可用集

当前标准模板：`通用人效分析看板_数据导入模板.xlsx`

### 2.1 工作表职责

| 工作表 | M1 必需性 | 粒度 / 用途 | 主要去向 |
|---|---:|---|---|
| `00_使用说明` | 说明 | 导入约束、更新顺序、口径注意事项 | 模板帮助 |
| `01_配置_指标映射` | 必填 | 场景、主产出、FTE 规则、人工成本范围、预警阈值 | 配置中心 / 版本治理 |
| `02_组织维度` | 必填 | 组织树、责任中心、有效期、组织版本 | `dim_org` |
| `03_人力投入_月度` | 必填 | 月 × 组织 × 岗位族 × 职级 × 用工类型 | `fact_workforce_month`、`fact_labor_cost_month` |
| `04_业务产出_月度` | 必填 | 月 × 组织 × 业务线 / 项目 | `fact_business_output_month` |
| `05_过程质量_月度` | 推荐 | 月 × 组织 × 岗位 × 指标长表 | `fact_process_quality_month` |
| `06_目标标杆` | 推荐 | 月 × 范围 × 指标 | `fact_plan_month` |
| `07_行动台账` | 推荐 | 预警 / 行动 / 责任人 / 复盘 | `fact_action` |
| `08_指标字典` | 系统基线 | 指标公式、适用性、解释与注意事项 | `dim_metric` |
| `09_自动诊断规则` | 推荐 | 规则事实、待验证假设、核验路径和建议动作 | 预警规则中心 |

### 2.2 最小可用导入（MVP）

1. `01_配置_指标映射`
2. `02_组织维度`
3. `03_人力投入_月度`
4. `04_业务产出_月度`

缺失 `05_过程质量_月度` 时，系统仍可生成经营、人力投入、成本效率和组织差异分析，但必须将过程归因、质量护栏和部分自动诊断显示为“数据未覆盖”。

## 3. M1 逻辑数据模型

```text
配置 / 主数据
  dim_period · dim_org · dim_job_family · dim_cost_scope · dim_metric

月度事实
  fact_workforce_month
  fact_labor_cost_month
  fact_business_output_month
  fact_process_quality_month
  fact_plan_month
  fact_action

派生层
  dws_org_efficiency_month
  dws_job_efficiency_month
  dws_forecast_feature_month
  mart_dashboard / mart_alert / mart_forecast
```

### 3.1 维表

| 对象 | 主键建议 | 关键字段 | 控制原则 |
|---|---|---|---|
| `dim_period` | `period_id` | 自然月、财务月、季度、年份、是否关账 | 所有事实表须落在同一标准期间 |
| `dim_org` | `org_sk` / `org_code + org_version` | 上下级组织、利润中心、前中后台、有效起止日 | 历史组织与当前组织不可混用 |
| `dim_job_family` | `job_family_code` | 岗位族、价值创造类型、指标包 | 仅用于组织/岗位聚合，不要求个人信息 |
| `dim_cost_scope` | `cost_scope_code` | 成本科目、是否纳入全口径人工成本 | 由财务与 HR 共同维护 |
| `dim_metric` | `metric_code + version` | 公式、字段依赖、方向、适用行业、版本 | 看板跨页必须引用同一编码与版本 |

### 3.2 事实表主键与必填字段

| 事实对象 | 逻辑主键 | M1 必填字段 | 说明 |
|---|---|---|---|
| `fact_workforce_month` | `period + org_code + job_family + job_level + employment_type` | `period`、`org_code`、`average_fte` | 岗位/职级可按数据成熟度逐步补齐 |
| `fact_labor_cost_month` | 同人力投入粒度 | `salary_cost`、成本构成、`labor_cost_total` | 全口径成本以系统重算值为准 |
| `fact_business_output_month` | `period + org_code + business_line + product_or_project` | `period`、`org_code`、`recognized_revenue`、`operating_profit` | 业务线/项目可为空，但组织与期间不可为空 |
| `fact_process_quality_month` | `period + org_code + job_family + metric_code` | `period`、`org_code`、`metric_code`、`metric_value` | 使用长表支持跨行业指标包 |
| `fact_plan_month` | `period + scope_type + scope_code + metric_code` | 目标或预算或至少一种标杆 | 用于预警、目标差与预测比较 |
| `fact_action` | `issue_id` | 异常范围、指标、行动、责任人、状态 | 个人姓名仅在授权工作台显示 |

## 4. 字段映射表（M1）

### 4.1 组织维度：`02_组织维度`

| 模板字段 | 目标字段 | 必需 | 校验 / 说明 |
|---|---|---:|---|
| `org_code` | `dim_org.org_code` | 是 | 唯一；不能包含前后空格；事实表必须可匹配 |
| `org_name` | `dim_org.org_name` | 是 | 同一有效期内与编码一一对应 |
| `parent_org_code` | `dim_org.parent_org_code` | 否 | 非根节点必须存在；不得形成循环组织树 |
| `org_level` | `dim_org.org_level` | 推荐 | 同一路径层级递增 |
| `business_unit`、`region` | 组织分析维度 | 否 | 可用于筛选和横向比较 |
| `org_type`、`front_mid_back` | 组织属性 | 推荐 | 用于组织结构与指标适用性 |
| `is_profit_center` | 利润中心标识 | 推荐 | 影响经营利润的责任边界解读 |
| `effective_start`、`effective_end` | 有效期 | 是 | 事实期间必须命中有效组织版本 |
| `org_version` | 组织版本 | 是 | 组织调整后同比需明确同口径/重述策略 |

### 4.2 人力投入与人工成本：`03_人力投入_月度`

| 模板字段 | 目标对象 | 必需 | M1 规则 |
|---|---|---:|---|
| `period` | `fact_workforce_month.period` | 是 | `YYYY-MM`；必须为闭合自然月 / 财务月 |
| `org_code` | 组织外键 | 是 | 必须匹配当期有效 `dim_org` |
| `job_family`、`job_level` | 岗位维度 | 推荐 | 缺失时落在“未分配”，不阻断集团级指标 |
| `employment_type`、`service_cohort` | 人员结构维度 | 推荐 | 用于新人爬坡、外包、用工结构分析 |
| `average_fte` | 核心分母 | 是 | `> 0`；按企业 FTE 规则折算 |
| `headcount_end` | 辅助人数 | 推荐 | 不能替代平均 FTE 做人均计算 |
| `hire_count`、`leave_count` | 人员流动 | 否 | 非负整数；用于供需与流失预测 |
| `manager_fte`、`frontline_fte`、`outsourced_fte` | 结构指标 | 推荐 | 不得显著超过 `average_fte`，差异需配置共享/重叠规则 |
| `productive_hours`、`available_hours` | 工时效率 | 推荐 | `productive_hours <= available_hours`；均非负 |
| `overtime_hours` | 健康护栏 | 否 | 非负；需与工时期间和组织边界一致 |
| `salary_cost`、`bonus_cost`、`employer_cost`、`welfare_cost`、`recruitment_cost`、`training_cost`、`outsourcing_cost`、`severance_cost` | 全口径人工成本构成 | 是（至少工资与总成本） | 按配置确定纳入范围；空值视为 0 前须确认 |
| `labor_cost_total` | 人工成本总额 | 是 | 由系统按成本构成重算，与上传值对账 |

### 4.3 业务产出：`04_业务产出_月度`

| 模板字段 | 目标对象 | 必需 | M1 规则 |
|---|---|---:|---|
| `period`、`org_code` | 共同分析边界 | 是 | 必须与人力投入处于同一期间、同一组织责任边界 |
| `business_line`、`product_or_project` | 业务下钻维度 | 否 | 用于项目 / 产品 / 客户层分析 |
| `output_model` | 主产出模式 | 是 | 货币型、数量型、项目服务型等须与配置一致 |
| `primary_output_name/value/unit` | 通用主产出 | 推荐 | 非货币型场景的核心产出 |
| `recognized_revenue` | 确认收入 | 是（货币型 M1） | `>= 0`；不得以签约、开票、回款混用 |
| `gross_profit` | 毛利 | 推荐 | 用于质量型价值分析 |
| `contribution_profit` | 贡献利润 | 否 | 可作为补充分析指标 |
| `operating_profit` | 经营利润 | 是 | 人均利润、单位人工成本利润唯一 M1 分子 |
| `cash_collected` | 回款 | 推荐 | 现金与收入质量护栏；不替代确认收入 |
| `quality_score`、`delivery_on_time_rate`、`customer_complaint_rate` | 质量护栏 | 推荐 | 数值范围、单位（0–1 或 0–100）须统一配置 |

### 4.4 过程、目标与行动

| 来源表 | M1 必填字段 | 校验要点 |
|---|---|---|
| `05_过程质量_月度` | `period`、`org_code`、`metric_code`、`metric_value` | `direction` 与指标字典一致；单位换算必须有配置 |
| `06_目标标杆` | `period`、范围、`metric_code`、至少一种目标 / 标杆 | `higher_is_better` 与预警阈值方向一致 |
| `07_行动台账` | `issue_id`、范围、指标、行动、责任、状态 | 每项行动必须关联可验证指标与复盘时间 |
| `08_指标字典` | `metric_code`、公式、字段依赖、方向 | 指标变更必须产生新版本，禁止覆盖历史解释 |

## 5. 核心指标公式与统一口径

所有公式默认在**同一统计周期、同一组织责任边界、同一组织版本、相同 FTE 口径**下聚合。

| 指标编码 | 指标名称 | M1 公式 | 单位 / 呈现 | 关键限制 |
|---|---|---|---|---|
| `AVG_FTE` | 平均 FTE | `Σ average_fte` | 人 / 人月 | 不能用期末人数替代 |
| `LABOR_COST_TOTAL` | 全口径人工成本 | `工资 + 奖金 + 雇主成本 + 福利 + 招聘 + 培训 + 外包 + 离职补偿` | 元 / 万元 | 取决于成本范围配置与财务确认 |
| `RECOGNIZED_REVENUE` | 确认收入 | `Σ recognized_revenue` | 元 / 万元 | 不与签约、开票、回款混用 |
| `OPERATING_PROFIT` | 经营利润 | `Σ operating_profit` | 元 / 万元 | 必须由财务确认 |
| `OUTPUT_PER_FTE` | 人均有效产出 | `确认收入 ÷ 平均 FTE`（M1 货币型） | 万元 / 人月 | 数量型 / 项目型改用配置主产出 |
| `PROFIT_PER_FTE` | 人均利润 | `经营利润 ÷ 平均 FTE` | 万元 / 人月 | 经营利润与 FTE 同边界 |
| `LABOR_COST_PER_FTE` | 人均人工成本 | `全口径人工成本 ÷ 平均 FTE` | 万元 / 人月 | 成本范围必须披露 |
| `PROFIT_PER_LABOR_COST` | 单位人工成本利润 | `经营利润 ÷ 全口径人工成本` | 倍 | 不能理解为因果贡献，只是效率比率 |
| `PERSONNEL_EXPENSE_RATE` | 人事费用率 | `全口径人工成本 ÷ 确认收入 × 100%` | % | 低不一定更好，需结合产出与质量 |
| `WAGE_REVENUE_CONTRIB` | 1 元工资贡献营收 | `确认收入 ÷ 工资总额` | 元 / 元工资 | 工资不含其他人工成本 |
| `WAGE_PROFIT_CONTRIB` | 1 元工资贡献利润 | `经营利润 ÷ 工资总额` | 元 / 元工资 | 经营利润可为负，需正确呈现 |
| `EFFECTIVE_HOURS_UTILIZATION` | 有效工时利用率 | `有效工时 ÷ 可用工时 × 100%` | % | 仅在工时口径可比时启用 |

## 6. 自动对账与数据质量规则

### 6.1 阻断发布规则（P0）

| 编号 | 规则 | 判断 / 容差 | 失败后的系统处理 |
|---|---|---|---|
| R-01 | 组织完整性 | 所有事实 `org_code` 匹配当期有效组织版本 | 阻断；列出未匹配组织、期间和行数 |
| R-02 | 期间一致性 | 收入、利润、FTE、成本使用同一期间粒度 | 阻断；列出错配期间与来源表 |
| R-03 | 人工成本构成 | `labor_cost_total = 各成本构成之和` | 阻断；默认容差 `max(1 元, 0.1%)` |
| R-04 | 人均回算 | `人均指标 × 平均 FTE = 对应总额` | 阻断；默认容差 `max(1 元, 0.1%)` |
| R-05 | 集团汇总 | 上级组织值 = 有效下级组织之和，或有明确未分摊共享中心规则 | 阻断；显示差额及组织路径 |
| R-06 | 主数据唯一性 | 同一事实逻辑主键无重复记录 | 阻断；显示重复键及行号 |
| R-07 | FTE 合法性 | `average_fte > 0`；不得为文本、负数或异常小数 | 阻断；提示 FTE 折算规则 |
| R-08 | 指标版本唯一性 | 同一指标跨页引用同一 `metric_code + version` | 阻断；禁止“页面各算各的” |

### 6.2 告警但允许发布（P1）

| 编号 | 场景 | 处理方式 |
|---|---|---|
| W-01 | 过程质量表缺失 | 发布基础经营看板；隐藏或标记过程归因为“未覆盖” |
| W-02 | 目标 / 标杆缺失 | 可看趋势与结构；预警只能基于规则或历史基线，须提示限制 |
| W-03 | 业务异常高值 / 低值 | 标记异常记录，要求确认是否一次性项目 / 会计调整 |
| W-04 | 可用工时为零或缺失 | 不计算有效工时利用率，不影响财务人效指标 |
| W-05 | 岗位族 / 职级缺失 | 允许组织级计算；岗位分析显示“数据覆盖不足” |
| W-06 | 历史样本不足 | 预测仅显示趋势观察，不发布正式预测结论 |

### 6.3 前端必须可解释的校验输出

每条校验结果至少展示：

- 状态：通过 / 告警 / 阻断；
- 规则名称与业务含义；
- 受影响期间、组织、记录数；
- 来源工作表与字段；
- 差异金额 / 数量；
- 推荐修复动作；
- 校验时间、配置版本、数据批次号。

## 7. 模板升级方案（V1.1）

### 7.1 不破坏既有用户的兼容策略

1. 保留现有 10 个工作表名称和核心字段；
2. 在每张数据表增加隐藏的 `template_version`、`batch_id`、`source_system`、`data_owner`、`loaded_at` 字段；
3. 新增列全部放在现有列右侧，导入程序按字段名而非列序解析；
4. 对历史模板使用“缺失字段降级规则”，不要静默补值；
5. 保留一个 `99_导入校验结果` 输出页，供导入人和数据 Owner 回填修复。

### 7.2 建议新增字段

| 工作表 | 建议新增字段 | 目的 |
|---|---|---|
| `01_配置_指标映射` | `config_version`、`effective_start`、`approved_by`、`approval_status` | 口径治理与版本审批 |
| `02_组织维度` | `org_owner`、`finance_owner`、`allocation_rule_id` | 组织责任与共享成本分摊可追溯 |
| `03_人力投入_月度` | `template_version`、`batch_id`、`source_system`、`fte_calculation_note` | 数据批次、来源与 FTE 解释 |
| `04_业务产出_月度` | `revenue_recognition_policy`、`allocation_rule_id`、`source_system` | 确认收入和责任归属可审计 |
| `05_过程质量_月度` | `metric_version`、`data_quality_flag` | 自定义指标治理 |
| `06_目标标杆` | `baseline_type`、`benchmark_source`、`approved_by` | 目标与标杆来源解释 |
| `07_行动台账` | `evidence_link`、`actual_impact_value`、`review_conclusion` | 行动验证和复盘闭环 |

### 7.3 导入 UI 需要与模板同步的内容

导入向导应固定为五步，而不止静态四步：

1. **上传与识别**：解析 Excel / CSV、显示模板版本和工作表覆盖度；
2. **字段映射**：以真实表头预填映射，允许保存组织专属映射方案；
3. **口径确认**：确认收入、经营利润、全口径人工成本、平均 FTE 的来源字段与版本；
4. **质量 / 对账校验**：分“阻断项、需确认项、已通过项”；
5. **发布与生成**：生成批次号、口径版本、影响范围，并进入经营总览。

## 8. 预测模型输入 / 输出定义（M1）

### 8.1 通用前置条件

- 历史月度样本：建议至少 12 个月；低于 12 个月仅趋势观察；
- 数据质量：`< 85 分` 时模型不可用或标记低可信；
- 回测：至少最近 3 期滚动回测；
- 可信度：
  - `MAPE ≤ 6%`：高可信；
  - `6% < MAPE ≤ 10%`：可用，展示置信区间；
  - `MAPE > 10%`：需复核，扩大区间，限制自动行动建议。

### 8.2 模型对象

| 模型 | 预测目标 | 最小输入 | 输出 | 行动使用限制 |
|---|---|---|---|---|
| 人均确认收入 | 未来 N 月确认收入 / FTE | 收入、FTE、需求 / 订单指数、季节性 | 点预测、80% 区间、目标差、MAPE | 不替代销售预算 |
| 人均经营利润 | 未来 N 月经营利润 / FTE | 收入、经营利润、人工成本、结构、质量 / 延期 | 点预测、区间、利润杠杆分解、MAPE | MAPE > 10% 时只能观察 |
| 人均人工成本 | 未来 N 月成本 / FTE | 成本构成、调薪、招聘、外包、FTE | 点预测、成本驱动、区间、MAPE | 必须标注成本范围版本 |
| 人员供需 | 未来 N 月在岗 FTE / 缺口 | 期初 FTE、招聘计划、达成率、流失、编制需求 | 期末 FTE、缺口、区间、MAPE | 仅支持组织级，禁止个人级预测 |

### 8.3 预测输出的审计字段

`model_id`、`model_version`、`trained_at`、`training_window`、`feature_snapshot_id`、`mape`、`data_quality_score`、`interval_level`、`approval_status`、`published_by`、`forecast_batch_id`。

## 9. 权限、隐私与治理

| 角色 | 默认可见范围 | 可编辑 | 可导出 |
|---|---|---|---|
| 经营管理层 | 集团 / 事业部聚合指标、预警、预测 | 不直接改原始数据 | 聚合经营简报 |
| HRBP | 授权组织的人力结构、行动、过程护栏 | 行动、数据问题反馈 | 脱敏 / 聚合明细 |
| 一线主管 | 本团队经营、交付、工时、行动 | 本团队行动进度 | 本团队授权摘要 |
| 财务 / 数据 Owner | 全量口径、对账、批次和指标血缘 | 配置、校验修复、发布 | 受控数据导出 |

禁止默认展示：个人薪酬、个人绩效、潜力、九宫格、稳定性备注、继任差距等敏感字段。

### 10.2 DoD（Definition of Done）

- [ ] 上传一份符合模板的文件后，系统生成唯一 `batch_id`；
- [ ] 必填字段、组织匹配、期间一致性、人工成本构成、人均回算、集团加总、重复主键、指标版本八类 P0 规则均执行；

- [ ] 默认无个人敏感数据，权限与导出日志可追踪。

## 11. 待业务确认的决策清单

1. 全口径人工成本是否包含奖金、雇主成本、福利、招聘、培训、外包、离职补偿；各项的会计科目映射是什么？
2. 兼职、外包、派遣、实习生、共享人员的 FTE 折算规则是什么？
3. 组织调整后，同比采用历史重述、同口径组织树还是双口径并列？
4. 共享成本与收入的责任分摊规则由谁维护、如何版本化？
5. 质量 / 健康度的红黄线、权重、内部与外部标杆由谁审批？
6. 预测的最小样本长度、重训频率、Model Owner、发布审批人分别是谁？
7. 情景模拟的杠杆系数来自历史统计、财务模型、专家规则还是实验？
8. HRBP、主管、财务和数据 Owner 的查看、编辑、导出权限边界是什么？

## 12. 推荐上线顺序

```text
M1.0：模板导入 + 映射 + 对账 + 基础看板
  ↓
M1.1：指标中心 + 预警 / 行动 + 组织下钻
  ↓
M1.2：过程质量数据 + 损耗金额化 + 行业指标包
  ↓
M1.3：预测模型治理 + 情景模拟 + 行动验证
  ↓
M2：审批后的系统直连、自动化任务和更丰富的数据治理
```

> **上线原则：** 先保证数据同源、口径一致、异常可解释、行动可验证；再扩大自动化与预测能力。
