## 项目简介

**人效经营驾驶舱**不是一份单纯的 HR 报表，也不是个人绩效排名工具。它以统一的数据口径连接业务、人员与财务信息，帮助经营管理者回答四个关键问题：

1. **人力投入去了哪里？** —— 工资、雇主成本、福利、外包及其他人工成本是否可对账；
2. **哪些组织真正创造价值？** —— 从收入、利润、人均产出、成本效率和质量护栏识别组织差异；
3. **哪些成本没有转化为经营结果？** —— 将新人爬坡、等待、返工、延期及低质量订单纳入解释路径；
4. **下一步应采取什么行动？** —— 将异常事实转成待验证原因、责任人、行动计划与复盘结果。

核心经营逻辑：

```text
人力投入 → 组织过程 → 业务产出 → 经营结果
                  ↕
       质量、客户、员工健康、人才稳定性护栏
```

当前仓库提供的是 **V6.6.1 离线单文件交互原型** 和 M1 数据治理设计资产。它适合产品评审、方案演示、指标口径对齐、导入流程验证和研发需求拆分；并非可直接替代生产数据平台的成品系统。

> **当前确认基线：V6.6.1。** 本版本以用户确认的 `人效经营驾驶舱.html` 为唯一原型基线，保留并整合了经营总览、投入产出分析、人均效能、组织地图、预警行动、预测中心、指标配置和真实本地导入能力。后续提交应基于此版本增量演进，不再以早期 V6.3 / V6.2 文件作为发布入口。

## 核心能力

### 1. 经营人效总览

- 经营管理层、HRBP、一线主管三类角色视图；
- “经营四问”总览与组织 / 岗位 / 过程下钻；
- 结果、成本效率、组织结构、人才成熟度、交付与质量联合解释；
- 规则型归因清单明确标记为 **待业务验证**，不伪装为实时 AI 因果结论。

### 2. FineBI 风格人均效能看板

- `1 元工资贡献营收`；
- `1 元工资贡献利润`；
- `人事费用率`；
- 营收、利润、人工成本、平均 FTE 的经营结果环形区；
- 各组织人效比较、趋势、人工成本构成及人员成本结构。

### 3. 标准模板真实本地导入（V6.6.1）

- 支持在浏览器本地读取 `.xlsx` 标准模板；
- 支持本地 `.csv` 基础读取；
- 不上传数据、不请求外部网络、不依赖 CDN；
- 识别标准工作表、表头、期间、组织、FTE、成本、确认收入、经营利润和过程指标；
- 可将真实导入数据发布为批次，并驱动总览、组织地图、人均效能看板与预测中心基线。

### 4. P0 / P1 数据治理

- **P0：阻断发布** —— 组织、期间、成本构成、人均回算、汇总、重复主键、FTE 合法性、配置版本；
- **P1：提醒与降级** —— 过程质量、目标与标杆覆盖不足时限制高级归因和预警解释；
- 发布后记录数据批次、组织版本、指标版本与数据血缘。

### 5. 预测—模拟—行动闭环

- 经营预测、情景模拟、模型治理、预测行动四个 Tab；
- 需求、招聘、招聘达成、流失、调薪、自动化等经营杠杆模拟；
- 预测不替代预算与管理判断；
- 样本不足、数据质量低或 MAPE 过高时，自动降级为趋势观察，不允许将预测自动转为行动。

## 快速开始

### 方式一：直接打开（推荐）

本项目没有构建步骤，也不依赖 npm 包。

1. 下载或克隆本仓库；
2. 使用最新版 **Chrome** 或 **Edge** 打开根目录的 `index.html`；
3. 进入左侧 **数据与指标配置** → **进入真实导入流程**；
4. 点击 **读取内置标准模板示例**，或选择 `data/templates/通用人效分析看板_数据导入模板.xlsx`；
5. 依次完成字段映射、M1 口径确认、P0/P1 对账；
6. 点击 **发布真实数据并生成分析**；
7. 查看经营总览、人均效能看板、组织人效地图和预测中心。

> 浏览器要求：`.xlsx` 离线读取依赖现代浏览器的 `DecompressionStream`。建议使用最新版 Chrome / Edge。Safari 或旧版浏览器如不支持，可先查看内置示例或改用 CSV。

### 方式二：本地静态服务器

直接双击 HTML 即可运行。如公司浏览器安全策略限制本地文件读取，可使用任意静态服务器，例如：

```bash
# Python 3
python -m http.server 8080
```

随后访问：

```text
http://localhost:8080
```

## 数据口径与指标体系

### M1 已确认主链路

| 指标 | M1 公式 | 说明 |
|---|---|---|
| 人均有效产出 | `确认收入 ÷ 平均 FTE` | 货币型经营场景的默认主产出 |
| 人均利润 | `经营利润 ÷ 平均 FTE` | 使用经过财务确认的经营利润 |
| 人均人工成本 | `全口径人工成本 ÷ 平均 FTE` | 人工成本范围必须配置且可追溯 |
| 单位人工成本利润 | `经营利润 ÷ 全口径人工成本` | 用于投入回报效率判断 |
| 人事费用率 | `全口径人工成本 ÷ 确认收入 × 100%` | 需与质量、客户及人才稳定性共同解释 |
| 1 元工资贡献营收 | `确认收入 ÷ 工资总额` | 工资总额不等于全口径人工成本 |
| 1 元工资贡献利润 | `经营利润 ÷ 工资总额` | 利润为负时须正确呈现，不做美化 |
| 有效工时利用率 | `有效业务工时 ÷ 可用工时 × 100%` | 仅在工时口径可比时启用 |

### 全口径人工成本

默认由以下构成实时汇总：

```text
工资 + 奖金 + 雇主成本 + 福利 + 招聘 + 培训 + 外包 + 离职补偿
```

正式上线前，必须由财务、HR 与业务数据 Owner 共同确认：

- 成本范围及会计科目映射；
- 兼职、外包、派遣、实习、共享人员的 FTE 折算规则；
- 组织调整后的同比重述逻辑；
- 共享成本与收入责任分摊规则。

更多信息见：[M1 数据接入与指标口径设计包](./docs/M1_数据接入与指标口径设计包_V1.0.md)。

## P0/P1 数据质量与发布规则

### P0：必须通过，否则阻断发布

| 编号 | 规则 |
|---|---|
| P0-01 | 所有事实记录匹配当期有效组织版本 |
| P0-02 | 收入、利润、FTE、成本使用同一统计期间和组织边界 |
| P0-03 | 人工成本总额与成本构成对账一致 |
| P0-04 | 人均指标可由对应总额与平均 FTE 回算 |
| P0-05 | 集团值可由下级组织有效数据加总，或应用明确分摊规则 |
| P0-06 | 月度事实主键无重复记录 |
| P0-07 | 平均 FTE 合法，工时数据合理 |
| P0-08 | 主产出、FTE 规则、人工成本范围及指标版本存在 |

### P1：允许基础分析，但必须明确限制

| 编号 | 场景 | 系统行为 |
|---|---|---|
| P1-01 | 过程与质量数据缺失 | 允许基础经营分析；过程归因标记“数据未覆盖” |
| P1-02 | 目标 / 预算 / 标杆缺失 | 允许趋势观察；目标差与预警解释能力降级 |

## 预测治理

预测中心服务于经营讨论，而不是替代预算或管理判断。

正式预测准入建议同时满足：

```text
历史月度样本 ≥ 12 个月
数据质量 ≥ 85 分
最近滚动回测 MAPE ≤ 10%
```

| 条件 | 系统策略 |
|---|---|
| `MAPE ≤ 6%` | 高可信，可展示较窄置信区间 |
| `6% < MAPE ≤ 10%` | 可用，必须展示置信区间与使用提示 |
| `MAPE > 10%` | 需复核，扩大区间并限制自动行动建议 |
| 数据质量 `< 85 分` | 不可用或低可信，禁止自动行动 |
| 历史样本 `< 12 个月` | 仅趋势观察，不发布正式预测 |

仓库的标准模板样例只有 2 个月历史，因此 V6.6.1 会自动显示“仅趋势观察”，不会把示例数据包装为正式预测。

## 部署到 GitHub Pages

本仓库根目录的 `index.html` 已是可直接发布的静态入口。

1. 将代码推送到 GitHub 的 `main` 分支；
2. 进入仓库 **Settings** → **Pages**；
3. 在 **Build and deployment** 中选择：
   - Source: `Deploy from a branch`
   - Branch: `main`
   - Folder: `/ (root)`
4. 保存后等待 GitHub Pages 构建完成；
5. 访问 GitHub 提供的 Pages 地址。

> 注意：GitHub Pages 适合展示原型；用户在页面中选择的 Excel 文件只会在其浏览器内被读取，不会被提交到仓库或上传到服务器。

完整上传指南见：[GitHub 上传与发布指南](./docs/GITHUB_UPLOAD.md)。

## 数据安全与使用边界

### 不要提交到公开仓库的数据

以下内容不应提交到 GitHub，尤其是公开仓库：

- 真实员工姓名、工号、联系方式；
- 个人薪酬、奖金、绩效、潜力、九宫格、继任与稳定性备注；
- 未脱敏客户信息、订单、项目、财务明细；
- 数据库连接串、令牌、密钥、内部接口地址；
- 未经审批的 HRIS、财务、CRM、项目管理系统导出文件。

`.gitignore` 已默认忽略 `data/uploads/` 和常见 Excel / CSV 导入文件。请只保留经过脱敏、确认可公开的模板与示例数据。

### 产品使用边界

- 人效看板用于组织级、岗位级和经营级分析；
- 不应用于默认公开的员工个人排名；
- “归因洞察”属于待业务验证的规则型假设，不等同于因果结论；
- 预测结果是经营讨论输入，不替代预算、审批和管理判断。

详细安全建议见：[SECURITY.md](./SECURITY.md)。
